# UPDATE 2026-07-28 — Rate-limit metadata + auto-discovery (ADR-007)

> Tác giả: 9Router Agent. Đề xuất: Sếp (Đức Trần) phê duyệt 2026-07-28.
> Phạm vi: 5 PR (#59 → #63). Cập nhật sau khi hoàn thành từng PR.

## 1. Bối cảnh

9Router hiện **không** có proactive throttle cho RPM/TPM/RPD/TPD:
- Chỉ phản ứng khi upstream trả 429/403 (reactive, xem [open-sse/config/errorConfig.js](../open-sse/config/errorConfig.js)).
- Không có limit metadata cho từng provider/model/connection.
- User phải tự cấu hình nếu muốn (hiện không có UI).

Hệ quả:
- Free provider (NVIDIA NIM, opencode, mmf) bị spam → upstream rate-limit → 9Router fallback hỗn loạn.
- Hôm nay (2026-07-28), `nvidia/z-ai/glm-5.2` DEGRADED function + timeout 250s do user spike; nếu 9Router throttle trước sẽ giảm tải cho upstream.

## 2. Quyết định

### 2.1 Limit resolution order (5 tầng, ưu tiên cao → thấp)

```
1. connection.limits      (user config per api-key)         — cao nhất
2. model.limits           (registry models[].limits)
3. provider.limits        (registry limits, default)
4. autoDiscoveredLimits   (DB cache từ 429 trước)
5. inferred (models.dev)  (heuristic từ limit.context)
6. null                   (no throttle)                       — thấp nhất
```

Provider cũ không khai báo `limits` → mặc định `null` (không throttle). Chỉ khi gặp 429/403 lần đầu mới tự fill vào `autoDiscoveredLimits`.

### 2.2 Cấu trúc dữ liệu

**Trong registry** (code-declared, immutable):
```js
// open-sse/providers/registry/nvidia.js
{
  id: "nvidia",
  limits: {                       // provider-level default
    rpm: 40, tpm: 1_000_000,
    concurrency: 5,
    source: "https://docs.nvidia.com/nim/free-tier",
  },
  models: [
    {
      id: "z-ai/glm-5.2",
      name: "GLM 5.2",
      limits: {                   // model override
        rpm: 30, tpm: 500_000,
        source: "https://build.nvidia.com/zai/glm-5.2",
      },
    },
  ],
}
```

**Trong connection data** (user-overridable JSON):
```jsonc
{
  "apiKey": "sk-...",
  "limits": {
    "rpm": 50, "tpm": 2_000_000, "rpd": 5000,
    "source": "user-configured"
  }
}
```
Phase 1: chỉ auto-fill, không cho user sửa tay (chờ UI ở PR sau).

**DB tables (mới, thêm vào schema.js)**:
- `rateLimitCounters` — sliding window events, persistent.
- `autoDiscoveredLimits` — lịch sử học từ 429, ghi đè lên lần sau.

### 2.3 Schema mới

```sql
CREATE TABLE rateLimitCounters (
  scope TEXT NOT NULL,         -- "{connectionId}:{provider}/{model}"
  window TEXT NOT NULL,        -- "rpm" | "tpm" | "rph" | "rpd"
  windowMs INTEGER NOT NULL,   -- 60000 / 60000 / 3600000 / 86400000
  events TEXT NOT NULL,        -- JSON: [{ts, tokens}]
  updatedAt INTEGER NOT NULL,
  PRIMARY KEY (scope, window)
);
CREATE INDEX idx_rlc_scope ON rateLimitCounters(scope);

CREATE TABLE autoDiscoveredLimits (
  connectionId TEXT NOT NULL,
  provider TEXT NOT NULL,
  model TEXT NOT NULL,
  rpm INTEGER, tpm INTEGER, rph INTEGER, rpd INTEGER,
  concurrency INTEGER,
  source TEXT,                 -- "auto-429-detection"
  evidence TEXT,               -- 429 body đã học (max 500 char)
  firstSeenAt INTEGER NOT NULL,
  lastSeenAt INTEGER NOT NULL,
  hitCount INTEGER DEFAULT 1,
  PRIMARY KEY (connectionId, provider, model)
);
```

`SCHEMA_VERSION` bump từ 1 → 2 (sau khi cộng 2 table mới).

### 2.4 Auto-discovery algorithm

**Trigger**: upstream trả 429 hoặc 403 với rate-limit hint.

**Parser** (`open-sse/diepxuan/limits/errorParser.js`):
- Headers: `x-ratelimit-limit-requests`, `x-ratelimit-limit-tokens`, `anthropic-ratelimit-*-limit`.
- Body regex:
  - `Requests limit = 40 / minute` → `{rpm: 40}`
  - `40 requests per minute` → `{rpm: 40}`
  - `1,000,000 tokens per minute` → `{tpm: 1_000_000}`
  - `usage_limit: 100/day` → `{rpd: 100}`

**Record**: UPSERT vào `autoDiscoveredLimits`. `hitCount++` mỗi lần thấy cùng limit (chứng minh reliable). Nếu 2 lần liên tiếp conflict giá trị → log warning, không ghi đè (giữ giá trị đầu tiên, an toàn hơn).

### 2.5 Throttle policy (3 chế độ)

Khai báo trong `limits`:
```js
limits: { rpm: 40, policy: "wait-then-send", maxWaitMs: 90_000 }
```

| Policy | Hành vi | Default |
|---|---|---|
| `wait-then-send` | sleep tới oldest event rời window, gửi tiếp | free provider |
| `reject-429` | fail fast, return 429 cho client, fallback chain chạy | paid API |
| `fallback` | skip sang model tiếp theo trong combo (giống skip hiện tại) | mặc định |

### 2.6 Sliding window implementation

`SlidingWindow` class trong `open-sse/diepxuan/limits/window.js`:
- Lưu events trong SQLite (persistent) thay vì memory.
- `prune(now)` xóa events cũ khi read.
- `oldestAgeOutAt(now)` tính thời điểm 1 slot free.
- Khi restart, events trong `rateLimitCounters` đọc lại từ DB. Tự `prune` các event cũ hơn window.

### 2.7 Hook integration

Mở rộng `beforeComboModelAttempt` trong `open-sse/diepxuan/comboHooks.js`:
- Sync → async (caller `services/combo.js` đã chấp nhận await).
- Thêm `acquireQuotaSlot({ connectionId, provider, model, estTokens })`.
- Return `{ skip: true, reason: "rpm_exceeded" }` nếu vượt ngưỡng và policy = fallback/reject.

Mở rộng `afterComboModelAttempt`:
- Record event vào `rateLimitCounters`.
- Trigger `extractLimitsFromError` nếu upstream fail 429 (chỉ lần đầu, sau đó đã có cache).

## 4. Backward compatibility

- Provider cũ không có `limits` → `null` → không throttle. **0 hành vi thay đổi** cho user hiện tại.
- 9Router chỉ bắt đầu throttle khi:
  (a) User mở combo mới, model khai báo `limits` trong registry (PR #59).
  (b) Hoặc upstream trả 429 lần đầu, auto-discovery ghi vào DB (PR #60+).
- Existing quota tracking (`usageHistory`, `usageDaily`) **không bị ảnh hưởng**. Tables mới là bổ sung.

## 5. Out of scope (deferred)

- Multi-region failover cho rate-limit (chỉ track 1 region).
- Per-endpoint limits (chỉ per-model).
- User manual edit UI (chỉ auto ở phase 1).
- Predictive throttle (dùng ML dự đoán khi nào sẽ vượt).

## 6. Risk

- **Counter drift**: nếu 9Router crash giữa request và record, counter có thể underestimate → upstream vẫn 429. Mitigation: dùng `usageHistory` reconcile mỗi 5 phút.
- **Auto-discovery sai**: parser regex bắt nhầm text trong error body. Mitigation: `hitCount >= 3` mới áp dụng.
- **DB growth**: events trong `rateLimitCounters` có thể tích lũy. Mitigation: background job prune events > 1 ngày, mỗi giờ chạy 1 lần.

## 9. Cập nhật 2026-07-31 — Context length + combo

Bổ sung sau ADR-007 ban đầu:

- **Context length source priority**: `api > static > error`. Error-derived values chỉ điền khi chưa có curated value. Sửa lỗi error 262144 chặn static 1M cho minimax-m3.
- **Combo context skip**: `beforeComboModelAttempt()` ước tính token request, nếu vượt context length model → skip, thử model tiếp theo ngay.
- **API `/api/models/context-lengths`**: trả context_length cho danh sách model ID, dùng chung nguồn với combo và `/v1/models`.
- **UI**: combo list/detail + provider Available Models hiển thị context_length từ hệ thống chung.
